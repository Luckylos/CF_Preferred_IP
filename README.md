# CF Preferred IP

CF Preferred IP 是一个候选 IP 质量选择核心：在统一候选池中同时衡量可用性、响应延迟、晚高峰长尾、证据量和不确定性，再决定哪些候选值得继续观察、晋升或发布。

安全边界：本仓库不是可直接连接真实节点的生产部署包。生产探测器、发布适配器、凭据、节点模板、实时状态和日志均被刻意排除。

## 包含内容

- rank.py：统一效用、方差感知置信界、晚高峰加权和发布粘性。
- admission.py：有容量上限的候选接纳与失败计数。
- cooldown.py：质量冷却与容量冷却的独立账本逻辑。
- atomic_io.py、ip_validation.py：状态写入和输入校验基础设施。
- replay.py：使用离线样本复盘排名。
- tests/：不访问外部网络的核心回归测试。
- examples/：仅使用文档保留地址的合成样例。

## 快速开始（离线）

要求 Python 3.11 或更高版本。运行时只依赖 Python 标准库；开发测试需要 pytest。

    cp config.example.sh config.local.sh
    bash scripts/offline_rank.sh
    python3 -m pytest -q -p no:cacheprovider

config.local.sh 和所有 *.local 文件都被 .gitignore 排除。公开仓库不需要、也不应该填写真实凭据。

## 数据和使用方式

排名 CLI 使用四类外部输入：历史样本、候选池、当前发布集和冷却账本。请参阅 docs/data-contract.md。

推荐的安全流程：

1. 在私有运行目录准备输入文件，不把真实历史、IP 清单、日志或发布结果复制进 Git 仓库。
2. 使用生产系统自己的探测/发布 adapter，把脱敏后的结构化样本交给本项目核心。
3. 在发布前执行离线回放和独立预检；本仓库不会替你连接节点或推送订阅。
4. 凭据放在仓库之外的权限受限目录（建议 0700），通过环境变量或 adapter 注入。
5. 生产状态文件只放在私有卷；公开仓库只保留合成样例。

## 设计摘要

- 失败样本效用为 0；慢响应按分段曲线降权。
- 对同一测量轮先去除公共拥塞，再比较候选的相对响应质量。
- 晚高峰样本提高重要性，但不虚增有效样本量。
- 排名使用效用的置信下界；证据不足的候选获得探索机会，不凭运气提前淘汰。
- 质量退出和容量退出使用不同冷却含义。
- 发布集采用粘性换位，避免小幅噪声造成频繁切换。

完整说明见 docs/design.md。

## 明确不提供

本仓库不提供真实节点配置、订阅生成、外部发布 API、凭据管理、生产 cron 或网络探测实现。因此，它 is not a drop-in production deployment（不是可直接替换生产部署的包）；也不要在公开 issue、日志或样例中粘贴真实凭据和节点地址。
