# 决策记录：Feel 评分是否改为尾部口径（p90）——离线回放结论：暂不改

日期：2026-10-15　状态：搁置（不改 score.py）

## 问题
主池中位 TTFB 已贴近 50ms 下限，`Feel = 0.67·u_ttfb(窗口均值) + 0.33·u_fail` 的 TTFB 项对所有 IP 接近满分。
怀疑均值掩盖了峰时尾部差异，考虑把 u_ttfb 的聚合从 mean 改为 p90 或 ½(median+p90)。

## 回放方法
以 2026-10-08..15 的 `vless_history.tsv`（7d 窗口、仅 master 52 IP）为输入，
在内存里替换 `score._vless_metrics` 的聚合函数，其余（stability / maturity / 分段曲线）不变，
对比三种口径的 Top5，并把窗口终点逐日后退 5 天检查 Top3 集合是否抖动。未写任何文件。

## 事实
- 尾部差异真实存在：52 个 master IP 中位数全在 47–53ms，但 7d p90 从 51ms 到 306ms；
  约一半（主要是 172.66.0.0/16）呈双峰：p90≈295–306ms，>100ms 样本占 12–34%。
- 但三种口径下 **Top3 集合完全相同**（104.21.55.188 / 172.66.43.117 / 104.18.32.113），
  只有 Top1/Top2 互换；5 天滚动窗口内三种口径 Top3 集合均 0 次变化。
- 差别只出现在候补位：rank5 由 162.159.129.87（p90=113）换成 104.21.47.37（p90=62）。
- 原因：stability 与 maturity 已经把高样本、零失败的 IP 顶在前面，均值口径下这些 IP 的 p90 本就 ≤90ms。

## 决定
- 不改 Feel 公式：发布集不变，收益为零，却要承担评分重排与回归风险。
- 真正的尾部问题在 **master 占位**：双峰 IP 单轮 median 正常，不会触发 `RETIRE_TTFB_DECAY`，
  长期占着 60 个席位里的约 25 个。若将来主池满员、好候选毕业后挤不进来，再考虑：
  1. 挑战者比较加入 7d p90 维度，或
  2. 用 `segment_quality.py` 对 172.66.0.0/16 做网段级判定。
  触发条件：`./status.py` 显示主池 ≥58/60 且试用池持续有 eligible>0 未入池。

## 复现实验
把本文件"回放方法"中的替换逻辑按 `score._vless_metrics` 的签名实现即可；
关键量：`p90 = sorted(pass_medians)[int(len*0.9)]`。
