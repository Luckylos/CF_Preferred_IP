# 周期结果 module 设计

状态：整体设计及隔离TDD实施已批准；部署与本地提交另行确认。

## 1. 意图、范围与不变项

把一次周期的证据、排名结果、应用确认和收尾事实变成可信、可解释的结果，避免调用方反复解释人类日志，也避免用旧成功掩盖新失败。

新增 cycle_result.py。cycle.sh继续拥有锁、调度、外部执行、历史追加和既有应用核验；rank.py继续拥有统计、排名、淘汰与发布选择；status.py继续拥有呈现和既有非周期监测。周期结果不是另一个排名模型。

评分、阈值、滞后、验证保护、冷却、准入及screen/probe控制流不变。保留set -euo pipefail、Python标准库及atomic_io.atomic_write。不修改verify_vless.sh、push_to_misub.py、apply.sh、segment_quality.py、systemic.py、publish_watchdog.sh。不读实际凭据、节点URL或原始应用指纹，不添加外部探测。

## 2. 已选方案与替代方案

- 已选：有depth的周期结果module，集中证据规则、机器结果、完整性、版本读取、保留与历史adapter。数据按周期独立保存，避免晚收尾覆盖。
- 未选：只把正则挪到新文件。虽然改动少，调用方仍要知道多个来源和何时能认定成功，depth不足。
- 未选：整个cycle迁入Python、共享总快照加写锁/索引，或数据库/事件总线。前者改变执行链过大；后者为本可独立保存的结果引入并发合并及额外故障面。

删除测试：若删除新module，版本、完整性、结果来源、保留和跨日志解释会重新散回cycle/rank/status。其leverage来自这些真实调用方；不建立可插拔adapter框架。

## 3. 小interface与归属

以下名称及存储路径是实现方提出、纳入本次整体审批的具体选择：

1. assess_audit：接收本轮审计执行证据，返回AuditEvidence（请求/返回数、最低行数、audit_ok、外部systemic、初始守卫）。原始审计格式由内部adapter处理；共享非统计规则同时供rank旧CLI事实输入使用。
2. begin_cycle / finish_cycle：开启与收束本次记录。返回CycleHandle，隐藏命名、路径、JSON、排序和清理。finish仅提交已发生的事实，不执行或重放业务动作。
3. RankReceipt：rank提交的机器结果。新增可选--result-out及覆盖率参数；不带新参数的旧CLI保留原行为和人类输出。receipt包含排名时间、摘要计数、发布建议、changed、最终guard、验证/退出分类及dry_run，不暴露统计内部对象。
4. read_status：返回最近尝试、最近完整结果、最近确切推送及来源/错误。内部有明确的JSON与历史日志adapter，调用方不用自己判版本、选日志或推断成功。

解析/序列化/排序/校验不是额外公共interface。日志增加可选cycle_id关联字段，保留原摘要内容与含义，便于新记录与日志确定去重。cycle不再靠grep排名摘要来取得业务事实；保留同样可读的rank/cycle日志内容，但从有效receipt组织摘要。status不再自行维护另一套周期结果/推送判定。

rank只写可选的临时receipt，不知道周期保留策略；cycle接收receipt并收束自己的最终记录。新module不导入rank，避免循环依赖。receipt不是第二份长期周期记录，正常退出与异常退出均清理，SIGKILL遗留按自身命名空间回收。

## 4. 记录与生命周期

生产：RESULT_DIR/cycle-results/cycle-<id>.json；shadow：CFST_DIR/.shadow/cycle-results/，与生产完全隔离。

每周期一份schema_version=1记录。包含：身份/模式/开始与结束时间、运行状态与退出码、审计证据、rank结果、应用确认、快筛/准入事实和警告；只允许受控字段，不复制stdout/stderr、凭据或原始指纹。应用确认由已有shell核验提供。

- 身份采用纳秒开始时间、模式与进程标识，不用UUID或全局索引。按开始时间及稳定ID选最新，不按结束时间。沿用单机日志时钟假设，不额外建立时钟框架。
- 共享锁获取后、开始业务副作用前先写open记录；拿不到共享锁的不持锁调用不创建新记录，仍保留既有忙锁行为。
- 正常收尾、显式提前返回、可捕获的失败走同一finish路径。已知非致命screen/MTR错误记警告，不改变原退出策略。
- slow仍按原时点释放fd9；它只能完成自己的文件，不能覆盖较新fast的文件。
- SIGKILL留下open。展示为“未收束”，不能断言仍在运行，也不能补造成功。后续周期从当前真实状态重新执行，不重放旧动作。
- 完成后的记录不可被另一周期改写；重复相同收束可无副作用，冲突收束报错。

内部维护仅处理本用户、自己的普通文件命名空间。沿用7天保留，另保留最近尝试和最近完整结果所需记录；按后续周期回收，不宣称满7天立即消失。原子临时文件及临时receipt沿用180分钟后下一次维护回收的保守方式，不触及凭据目录或别的临时文件。

## 5. 事实含义与完整结果

运行状态区分open/completed/failed/skipped。以下字段不能互相替代：

| 事实 | 可用证据 | 不能据此推断 |
| --- | --- | --- |
| 排名变更 | 有效RankReceipt.changed | 已应用、本轮已推送 |
| 应用确认 | 现有shell规则确认期望与已应用状态一致 | 本轮发生过推送 |
| 确切推送 | 能明确归属的现有成功标记 | 客户端已取得或实际使用 |

“无需应用”只描述原链路本来不要求应用的情况；维护闸门不能绕过原有状态核验。dry_run receipt不能冒充真实周期的已应用结果。

apply退出0本身不构成推送证据。保护脚本不改；无法可靠归属的本轮推送保持unknown。历史adapter集中读取slow/fast/cron既有成功标记，提供带来源的最近确切推送；不能凭时间接近硬凑为本轮推送。

最近完整结果仅由以下事实派生：周期正常收束、rank退出0且receipt有效、应用状态明确为已确认/无需应用/shadow不应用。它不要求本轮新推送，也不表示候选完成“完整验证”。

- no_evidence/coverage/systemic合法守卫可以形成完整结果；完整不等于采样充分或本轮全绿。
- rank失败、receipt缺失/损坏、应用未确认不更新最近完整结果。
- 缺tiers或审计锁忙导致未运行rank，仅成为最新尝试中的skipped，不冒充完整排名。
- 非致命快筛/MTR错误必须可见，但不擅自升级为排名或应用失败。

## 6. 守卫兼容

实际代码已逐行核对：cycle初始判断与rank非统计初始判断的现有优先级一致，均为no_evidence → systemic → coverage → none。

module集中该规则，cycle传入现有MASTER_MIN_COVERAGE_PERCENT；rank独立CLI默认80%。保留原覆盖检查适用前提（requested>0且返回数已知）和ceil(requested×percent/100)语义；正常正阈值至少1行。rank直接CLI的0/缺省审计参数及现有配置0%情况保持原行为，不把unknown补成0或另加惩罚。测试零值、非整除与临界值。

rank仍可基于历史将none补充为systemic。记录审计初始判断和rank最终guard两项事实，不将后者偷偷用作快筛/probe开关。缺省审计参数、审计失败、75忙锁、原systemic检测fail-open等旧调用语义都保持。

## 7. 读取、历史兼容与故障

- 新记录存在时严格验证版本、必需字段、类型、合法状态及完整性；不能把坏字段补成0/成功。未知版本、坏JSON、读失败明确返回问题。
- 最近尝试可为失败、跳过、未收束或损坏。最近完整结果可以较旧，但必须显示各自时间和来源；不把较旧成功显示为最新正常。
- 没有新记录时才把旧日志作为旧周期结果来源，并标明legacy；坏新记录不能静默伪装成“只有旧日志”。既有推送标记作为独立确切证据仍可读取。
- 新数据存在时，status不要求先有20*.log才能展示。slow/fast及既有轮转均考虑；保留旧慢轮/扫描/影子监测，不把未到slow周期误判为本次已实机验证。
- 七日流动同一次执行只算一次。能对应新记录的日志不重复累计；不能可靠归属的历史只展示已知事实，不补造数量或因果关系。
- begin写失败则不开始后续有副作用动作；finish写失败非零报错，不回滚已完成采样/排名/应用。错误类别和阶段写现有stderr日志，不抄原始异常数据。
- 若结果存储本身不可写，不能保证在该存储保存失败记录。以非零退出/可用的既有日志报告，旧记录明确是旧记录；不声称已保存一份不存在的最新失败。
- receipt/记录路径与其他输入输出重合、软硬链接别名及非法配置在副作用前拒绝；读写错误传播，不装作空成功。模块写入只用atomic_io，单文件原子，不宣称跨文件事务或exactly-once。
