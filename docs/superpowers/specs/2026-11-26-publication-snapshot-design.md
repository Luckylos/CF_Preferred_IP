# 候选 02 · 统一发布快照

## 期望发布

本轮审计决定是否允许新发布。通过本轮审计的排名将有序发布集、发布首选和 DNS 防抖状态放在一次原子文件替换里。建议使用版本化的 `.publish_desired.json`。排名用同一份快照读取在位成员和防抖状态，保留参考路径与上次有效胜场。同一批次重算不得计第二次胜场。守卫轮保留原快照。

`best_ips.txt` 继续输出人读榜单和现有机器可读段，供历史和展示调用者使用。自动发布读取一次快照，即可得到有序 MiSub 成员和 DNS 目标。即使榜单先写或后写，自动发布也只看到一个完整版本。发布首选必须属于发布集。没有可用首选时按既有规则从同一发布集取 DNS 目标。

## Interface

期望发布 module 提供读取和原子保存。排名持有唯一写入口。读取返回经校验的不可变值，包含有序发布集、发布首选和 DNS 防抖状态。发布入口从这份值和本次运行的发布配置解析实际通道、地址与配置指纹。DNS、MiSub、周期应用确认和发布看门狗的期望状态比较均依赖这一个 interface。快照只保存地址及决策状态。应用指纹沿用现有通道、模板和凭据摘要口径。

在应用锁内读一次期望发布。把解析得到的目标直接交给两条 adapter。普通发布和守卫重试都不让 MiSub 再读榜单。九个受管节点、HK/HT/SG 的槽位和参数沿用现有映射。DNS 保持单 A、TTL 60、关闭代理，以及现有写入顺序与精确读回。MiSub 保留跨订阅引用保护及读回。周期核对期望指纹和已应用指纹时读取完整快照。若发布中的期望版本推进，已完成的应用记录仍归属于实际使用的指纹。

删去这个 interface 后，排名、两路发布和状态检查就要分别协调成员、首选及重新读取的时机。保留该 interface 将这些约束集中于一个 seam，测试可通过同一入口验证两条 adapter 收到的目标。

## 跨轮重试

| 本轮状态 | 期望和待发布的关系 | 行为 |
| --- | --- | --- |
| 守卫或独立默认重试 | 指纹完全相同 | 用该快照重新核对两路并补齐 |
| 守卫或独立默认重试 | 无待发布，或指纹不同 | 保留记录，跳过两路调用 |
| 允许新发布 | 有不同指纹的待发布 | 原子记录当前获批指纹，按当前快照核对两路 |
| 允许新发布 | 期望回到已应用指纹，仍有待发布 | 重新核对两路，防止旧轮部分成功已改变远端 |
| 允许新发布 | 期望等于已应用，且无待发布 | 按现有条件跳过 |

在远端操作前写好待发布指纹。只有生产配置中的 DNS 和 MiSub 都读回目标才确认完成。任一路失败或响应丢失，保留待发布，重试先核对远端实际状态。一轮开始后始终使用该轮捕获的目标。若期望已推进，旧轮即使成功也只确认它实际发布的指纹。DNS 与 MiSub 各自保留原有的部分失败处理。

## 切换与验收

首次切换在现有锁内从发布集和 DNS 防抖状态生成快照，逐项比对原有目标及期望指纹。保留现有已应用与待发布记录。切换以本地比对为验收，不触发主动推送。启用后缺失或损坏的快照应导致发布停在校验处。切回时在同一组锁内把最新快照投影回旧读者使用的榜单与 DNS 防抖文件，再比对目标和指纹。保留届时的已应用和待发布记录。

隔离验收覆盖以下行为。

- 发布途中替换榜单或快照，两条 adapter 仍使用同一快照，确认归属于实际读回的指纹。
- 在位首选被移出发布集，相同批次重跑、参考路径变化和首选换位时保留已有防抖规则。
- 守卫遇到旧待发布、新期望或配置指纹变化时，旧记录保留且两路无调用。
- DNS 已成功、MiSub 未完成，随后换目标或回到已应用目标时按表执行。
- 写入响应丢失后重试读回当前远端状态，避免重复建记录或提前清除待发布。
- 快照缺失、损坏和写入中断时保留应用状态。切换前后的本地目标与指纹一致。
