# Design

## Goal

让真正可靠且低延迟的候选尽快浮出水面，同时给新候选完整的高峰验证机会，避免旧的中庸候选长期占位，也避免凭少量样本误删潜力候选。

## Scoring

每个有效样本先按同轮基线去除公共拥塞，再通过分段响应效用曲线转换为 s：失败为 0，快速响应接近 1，严重长尾接近 0。样本权重由时效衰减和晚高峰相关性构成。

- mu：加权效用均值。
- sigma：加权离散度。
- n_eff：时效权重和 Kish 有效样本数的较小值。
- lcb 和 ucb：带基础方差项的置信区间。

排名和淘汰主要看 lcb；探索和保护主要看 ucb。因此，低失败但高长尾的候选不会因为“能连通”就自动胜出。

## Validation lifecycle

候选的“完成验证”是持久状态，不随滚动评分窗口撤销。完成一次验证需要同一晚覆盖 20–21、22–23、00 三个时段，并满足最低有效证据量。历史完成状态不赋予永久发布资格；发布仍需要近期证据、低失败率和足够有效样本。

## Capacity and exits

池容量是硬上限。未完成验证的候选不因相对排名或容量直接退出；容量退出只从已有完整证据的候选中选择。没有合法退出者时应暂停接纳，而不是扩容或牺牲未验证候选。

质量冷却和容量冷却分开：容量退出说明资源取舍，不等同于质量判坏。发现和筛选都尊重相应冷却集合。

## Publishing

发布采用粘性换位：候选必须在保守下界上超过现任足够的 margin 才换位，并保留多样性约束。这样能避免单次噪声导致发布集抖动，同时允许有明确证据的新候选最终进入发布集。

## Production boundary

本公开仓库只提供确定性核心和离线输入合同。网络探测、凭据、发布 API、cron、锁和运行状态属于部署层，应由私有 adapter 实现并独立审计。
