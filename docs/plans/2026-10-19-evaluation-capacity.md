# 晚高峰验证与容量管理实施计划

目标：单一候选池内，未完成有效晚高峰覆盖的候选不参与相对淘汰；入口按空位背压，质量冷却与容量冷却分离。评分公式、发布资格和滞回不变。

1. 补回归测试：跨午夜覆盖、重复快周期、系统性轮、持久状态、四列兼容、相对淘汰保护、硬失败退出、空位预算、容量冷却及沙箱慢周期。
2. rank.py 增加 evaluation_completed_at（第五列，兼容四列），按入池后同一晚的 20/22/00 时段有效观察及 n_eff≥8 回填；完成状态不随 24h 滚动撤销。只有已验证且 n_eff≥8 的候选可被 unworthy/overflow 退出。
3. 所有冷却写入复用原子写入；overflow 进入独立容量冷却（6h），其他退出仍为质量冷却（24h）；发现与快筛都排除生效冷却。
4. 慢周期预算 min(20, POOL_MAX−当前池大小)，准入按请求集合去重并严格限额，原子保留已有五列元数据；等待或快筛运行失败不增加候选失败次数。
5. 同步现行设计与状态可观测字段；运行全量测试、语法检查、历史回放与独立差异检查。
6. 持生产 flock 原子替换，保守迁移可识别的既有容量冷却，不恢复历史退出者；先初始化持久验证状态，再恢复调度，核对容量与资源回收。本地提交，不推送。

验收：未完成验证的 unworthy/overflow=0；正常运行不超过 POOL_MAX；强失败及守卫保留；已验证状态持久；所有新状态写入 atomic_io；测试不触网。
